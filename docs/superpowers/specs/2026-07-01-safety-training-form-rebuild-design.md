# 承攬商線上安全衛生教育訓練表單 — 重建設計文件

日期：2026-07-01

## 背景與動機

目前 repo 裡的 `index.html` 是先前依「猜測」重建的 Google 表單網頁版，這次重來一遍，改為根據**真正的 Google 表單原始資料**（透過 Google Drive 存取、解析表單公開 HTML 內嵌的 `FB_PUBLIC_LOAD_DATA_`）逐欄核對重建。

比對後發現兩個關鍵落差：

1. 真正的表單有一個「電子郵件」必填欄位，且是 Google 的**驗證式電子郵件**（欄位 readonly、自動帶入登入者帳號），這代表**填寫人必須先登入 Google 帳號才能送出**。目前 index.html 完全沒有處理這個欄位。
2. 實測直接 POST 到原表單的 `formResponse` 網址會回傳 **HTTP 401**（伺服器端擋下未登入的請求），證實現行「`fetch(..., {mode:'no-cors'})` 直接 POST」的送出技巧已經失效。

為了解決這個問題，使用者已經**複製了一份表單副本**並關閉「收集電子郵件地址」設定（改為「不收集」），本設計文件之後的所有實作都會指向這個副本。

## 視覺設計

延續現有「藍＋琥珀」工業安全風格（`--blue: #1E5CC8`、`--amber: #C47A00` 等既有變數精神），這次用 frontend-design 技能重新設計版面排版、間距、字體層級與 3 步驟精靈的呈現方式，而非更換配色系統。

- 頁首加入瑞昱半導體 logo（藍色電路板意象標誌），以 base64 內嵌方式放入 HTML（維持「單一檔案、無外部相依」的特性），不使用外部圖片連結。
- 頂部維持步驟進度指示（3 步驟版本，取代現行單頁捲動的 progress-dot 概念）。

## 送出流程

1. 使用者完成步驟 1、2（含驗證）與步驟 3 全部作答（10 題皆需選填，但不要求全對）
2. 點擊送出：透過 `fetch(FORM_ENDPOINT, {method:'POST', mode:'no-cors', body: data})` 方式，將所有 entry 值送到副本表單的 `formResponse` 端點（沿用現行 index.html 的做法，不用 hidden iframe）
3. 送出後顯示完成畫面：感謝訊息＋測驗結果摘要（答對題數、答錯題號列表）

## 測試方式

沒有自動化測試框架，採手動驗證：

1. 本機開啟 `index.html`，依序走過 3 步驟
2. 步驟 2 故意選「否」/「不同意」，確認被擋下無法進入步驟 3
3. 步驟 3 刻意答錯幾題送出，確認仍能成功送出，且完成畫面正確顯示答對題數與答錯題號
4. 步驟 3 全對送出，確認完成畫面顯示「全對」的結果
5. 送出後前往副本表單的 Google 試算表，確認每筆測試資料的欄位與答案內容都正確對應，測試完手動刪除這些假資料列
